# V5.9 三资料对比研究流程 — 规格

基线：`dae1bccd3837b582216e753a7f931ef918658218`。本阶段只把已有的资料、Agent、引用和反馈串成一个可信的首次使用流程，不引入新的模型能力。

## 用户任务

首次使用者能够选择一个知识空间，准备至少三份已建立有效版本的技术资料，明确比较维度，提交只读的对比研究；完成后从报告中的事实结论进入证据原文，并能对错误结论提交反馈。全过程不把演示数据冒充真实结果。

## 可观察行为

1. 工作台有清晰的“三资料对比”入口和准备进度。缺空间、少于三份有效资料、资料尚无可用版本时，说明下一步并提供正确入口；失败或退役的资料不得误标为“处理中”。普通问答仍可使用一份有效资料。
2. 对比流程要求用户选择至少三份有效来源和一个或多个比较维度。提交给现有 Agent 的目标文本明确包含用户写的问题、比较维度和“分别列出证据、冲突与缺口”的要求；来源 ID 固定在现有范围快照中。输入上限与现有 4000 字边界一致，不在页面外悄悄截断。
3. 工作台在真实模式下读取现有系统状态，提前说明 LLM（语言模型）、Embedding（把文字转成检索向量）、Qdrant（向量库）等缺失项。配置状态不明时标为“不确定”，最终仍由后端拒绝不满足条件的提交。演示模式始终明显标记为录制样例。
4. 从上传中心进入的用户可以回到同一知识空间的对比流程；上传任务未完成时不能把来源当作可用证据。上传中心不伪造 OCR、索引或模型结果。
5. 提交失败时保留用户输入及同一次提交的请求编号；如果任务已创建但详情暂不可读，只恢复该任务。运行页刷新、取消和报告页的证据跳转/反馈沿用现有持久化契约，在本阶段用浏览器回归覆盖。
6. 报告页显示可读的“结论—证据—原文”路径；找不到资料或证据不足时如实显示缺口，不自动写入知识库。

## 验收接缝

- 浏览器公开页面：`/workbench`、`/upload`、`/runs/[runId]`、`/artifacts/[artifactId]`。断言用户可见内容及公开 HTTP 请求，不测试 React 内部状态。
- 后端现有公开接口：空间/来源目录、系统状态、创建与读取 Agent Run、成果与证据、反馈提交。新功能优先复用这些接口；如果确需新接口，必须做后端合同测试。
- 反例先失败，再做最小实现；每条纵向流程自检后才继续。完成后跑前端单测、lint、类型检查、正式构建，相关后端回归和独立规范/需求双轴审查。

## 明确不做

- 不配置或调用用户的真实付费模型，不把录制样例说成真实质量评测。
- 不新建多智能体、自动评分、策略自动启用或数据写入工具。
- 不将当前单用户本地应用直接开放公网；Docker 不可用时，不把依赖 Docker 的严格端到端套件记成通过。
