# 三份资料对比：这轮到底升级了什么

这轮没有给 Agent 换“大脑”，也没有假装接上了真实大模型。它解决的是第一次使用时的断点：用户过去要自己猜先去哪里上传、何时资料已经可用、选哪种研究模式，以及报告里的话怎样回到原文。

## 按一次实际使用来看

1. 在研究工作台选择“三资料对比”。页面只统计当前知识空间里**已经有可用版本的文档**；只有文件名、还没有可用版本的上传不会凑数。缺资料时，按钮直接通向同一空间的上传页。
2. 上传页锁定刚才选的知识空间，只显示这个空间的文档，并明确区分“文件已上传”和“内容处理、建立索引完成”。处理完返回原空间，不会误把文档传进别的知识库。
3. 写下要解决的问题、比较维度，并明确勾选至少三份资料。页面把“逐份列证据、指出冲突和缺口”与用户问题合成研究目标，仍受原有 4000 字上限保护。对比报告和分步 Agent 模式由流程固定，避免第一次使用时要猜内部选项。
4. 真实模式先读服务状态：语言模型、文字向量生成、向量库和任务队列哪项没准备好，就提前说清楚；最终能否启动仍以后端检查为准。录制演示可以练习流程，但会一直写明“不调用真实模型、结论不是实时生成”。
5. 原有运行记录、人工审批、结果页和精确证据链接仍然沿用。录制示例为三份资料分别准备独立的来源版本、片段和哈希，完成后有三条示例结论；点引用可以到对应原文位置。真实成果则沿用已有反馈入口，用户可以指出错误，反馈不会自动变成事实。

## 关键技术词（也是实现方法）

- **RAG（检索增强生成）**：先从上传资料中找相关原文，再让模型据此回答。这里没有直接把三份全文塞给模型，而是复用已有检索和引用链路。
- **Agent（智能体）**：把问题拆成步骤，检索、判断证据、整理结果，必要时停下来等用户批准。这轮的对比流程复用现有 Agent，而不是另建一个虚假的“多智能体”。
- **Revision（资料版本）**：文档某次处理后的固定内容。只勾选存在有效版本的文档，避免引用尚未处理完成的文件。
- **Chunk（证据片段）**：从文档中切出的可定位小段。报告的引用绑定片段，而不是只给文件名。
- **Hash（内容指纹）**：内容变化后会随之变化的标识。它与资料版本、片段及页码等位置一起构成可复查的引用。
- **Embedding（向量生成） / Qdrant（向量库）**：前者把文字变成方便检索的数字表示，后者保存这些表示；未配置时页面不能声称真实研究已准备好。
- **Recording（录制样例）**：固定示例事件，用来演示页面操作。它不调用模型，也不能用来证明模型回答质量。
- **Feedback（反馈）**：用户指出报告或某条结论的问题。系统保存待审阅记录，不会因为有人提出意见就自动改写原始资料。

## 还没有被证明的事

没有真实模型凭据，就不能验证真实回答是否有用；没有可启动的 Docker 服务，就不能把依赖 Qdrant、Redis 的严格端到端成绩写成“本次通过”。本轮能证明的是页面流程、请求边界、录制演示和自动化回归；真实数据效果要在模型、服务和业务文档到位后单独评测。
