# V5.10：研究过程与证据可靠性

基线：`99b47827ecf0df0df433d5bf69246b04305b2441`。工作分支：`codex/v5.10-research-reliability`。本阶段延续三资料对比，修复审查发现的真实断点；产品显示版本暂保持 V5.8。

## 用户可观察的目标

1. 显式选择来源的提交必须完整固定这些来源。来源不存在、已退役、属于其他空间或没有可用 revision/index 时，后端明确拒绝，不能静默缩小研究范围；revision/index 必须属于所选来源且相互匹配。拒绝不留下任务/命令/outbox。既有请求先幂等重放，即使来源后来退役也返回原任务。未限定来源的普通研究沿用当前规则。
2. 多来源 `comparison` 成果必须对每个固定来源具有已关联的支持或矛盾证据；只有被检索到、但未被采纳的候选证据不能凑数。缺来源证据时输出明确的来源缺口，不能发布完成的对比成果。该规则只证明来源覆盖，不声称每个比较维度都已充分证明。
3. 定量冲突判断需要相同的事实语境。不同方案、指标、时间范围和数值范围的正常差异不能仅因单位相同、数值不同而被判为矛盾；同一事实语境的不同值仍需要暴露冲突。不能可靠判断的复杂改写保持保守。
4. 当前浏览器标签页刷新、去上传页再返回时，可以恢复研究问题、比较维度、模式、知识空间与有效来源选择，以及预算/交付物/执行模式。可编辑草稿有效期 24 小时，状态按现有输入合同限制长度/类型；显式 URL 的模式/场景/空间优先于不相符草稿，普通刷新沿用对应草稿。损坏、过期、浏览器禁止存储时页面仍能使用；无法保存时不能声称刷新可恢复。不得保存密钥、服务器内部证据或隐藏思维。
5. 不确定的创建响应或详情读取失败后，刷新再重试保持同一请求编号；拿到任务编号后只恢复该任务。不可变的原始待确认请求与可编辑草稿分别保存，不随草稿过期或来源过滤自动改变，不自动发起任务。切换真实/录制模式、变更提交内容和明确清除草稿不得错误复用旧身份；仍可手动恢复原请求。清草稿需说明未确认任务没有被取消。
6. 运行结果为证据不足时，可以直接打开已保存的缺口报告，查看没有完成的研究部分。
7. 真实服务检查遇到 HTTP/业务失败必须返回非零退出码。总检查必须区分浏览器跳过与通过；严格检查不允许把未安装浏览器工具记为通过。受控浏览器回归与 Docker 真实服务验收分别报告。

## 验收接缝

- 后端：`EvidenceAgent.submit/inspect`、公开成果查询、`AgentRunner.advance_one`；隔离 SQL 数据库与确定性的检索/模型适配器，仅验证流程合同。
- 前端：公开工作台、上传、运行页面，公开 HTTP 请求与浏览器刷新；存储模块公开接口可做损坏/过期/存储失败测试。
- 运行检查：脚本公开命令和可见退出码/报告状态，外部 HTTP 与进程适配器允许受控替代。
- 先复现高风险反例，再修复对应纵向流程；分工窗口各自自审、聚焦回归后，总控做全量检查和独立规范/需求双轴复审。
