# V5.5 通俗指南（Plain Language Guide）

## V5.5 解决了什么问题？

V5.4A 的自动调音师能推荐"哪组旋钮最好"，但推荐只是一段文字——你还得
手工把那组旋钮位置抄到正式策略表单里。V5.5 把这段路修通了：

1. **一键转草稿（convert-draft）**：点一下，推荐候选的配置就变成正式表里
   的一行"草稿策略"。注意它只是草稿——上线仍要人工走 V5.3 那套需要
   60/60 满分评测的激活流程。转草稿是幂等的：手抖点两次也只会有一行，
   重复请求会告诉你"已经转过了"。
2. **对比视图（diff）**：可以查"这个候选和现在正在用的策略差在哪"，
   系统逐字段列出：左边是当前生效值，右边是候选值。
3. **实验收尾不再悬着**：以前如果所有候选都评测失败，实验会卡在
   "进行中"。现在会正确标记为"失败"；只要有一个成功就是"完成"。
4. **失败重试**：某个候选因为临时故障（比如 worker 崩了）失败，可以让它
   重新排队再跑一次，不用重建整个实验。
5. **手动止损**：发现实验跑偏了，可以一个请求把它标记为失败并终止所有
   还没跑完的候选。

## 为什么转草稿是安全的？

- 转出来的永远是"草稿"状态，代码里没有任何一条路能把它变成"生效"。
- 生效策略永远只有一个（数据库唯一索引强制），切换必须走人工激活 +
  满分评测双重门。
- 每个候选只能转一次草稿（数据库唯一约束强制），不会产生重复策略行。
- 配置转过去之前会再验一次指纹：写的和测的必须是同一份配置。
