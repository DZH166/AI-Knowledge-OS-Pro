# 这次页面到底改了什么，为什么会更好用

日期：2026-10-04。范围：四个核心页面的界面与交互，不是新的后端或模型升级。

## 一句话理解

把“大标题、介绍词、装饰卡片占主要位置的 AI 展示页”，整理成“问题、资料、操作和证据占主要位置的研究工具”。不是靠堆动画来提高质感。

## 1. 为什么原页面显得像通用 AI 模板

主要问题是标题过大、首屏留白多、说明重复、关键资料选择被折叠起来。用户要先读很多介绍，才能找到真正要操作的内容。

这次统一了字级、边框、间距和色彩：白色内容面板、灰色工作区域、一个低饱和绿色主色。侧栏缩窄；大标题收小；开发工具继续放在次级入口，不争夺研究入口的注意力。

实现位置：`frontend/app/globals.css` 和 `frontend/components/evidence-agent/EvidenceAgent.module.css`。CSS 是控制网页外观的样式规则；CSS Modules 是把组件样式隔离起来，避免一个页面的样式误伤另一个页面。

## 2. 怎么让研究入口更好操作

桌面上把“问题和运行设置”与“本次使用的资料”并排放置，手机上按顺序排列。资料选择不再藏在折叠设置里；可直接按名称或类型搜索，旁边始终显示已经固定了多少份资料。

搜索只改变当前看到哪些选项，不改变实际选择。即使暂时搜不到已经勾选的资料，它也不会被自动取消。原有草稿恢复和网络失败后的原任务恢复逻辑保持不变。

预算标签也改成能直接看懂的“标准 · 最多 8 步”等说明；数字来自原有共用配置，不另写一套可能过时的数字。

实现位置：`Workbench.tsx`。React 是组织界面和状态的前端框架；这里调整的是它如何呈现现有能力，不是改后端的研究规则。

## 3. 流畅性怎么改善

这次主要减少“不必要的工作”，而不是承诺某个没有测过的速度百分比。

- `useDeferredValue`：先让输入框响应打字，再更新资料筛选结果。不是把网络请求延迟，也不会修改已选范围。
- `memo`：当资料列表的输入没有变化时，复用已经渲染的结果。把整个列表隔离出来，避免每敲一个字都让旧列表重新处理一次。
- `useMemo`：资料统计、过滤结果和空间映射在相关输入没有改变时复用，减少重复计算。它不是持久数据库缓存。
- `content-visibility`：资料卡片滚动到屏幕之外时，浏览器可以暂缓绘制。用户滚动到该区域时再绘制；数据和可访问内容不被删除。
- 加载占位：等待时显示简洁的内容轮廓与文字状态；短暂动画有次数上限，系统选择减少动态效果时关闭动画。

尚未测大规模真实资料、低端手机或浏览器性能分数，因此不能说“速度提升了 X%”。

## 4. 可视化为什么没有漂亮的完成百分比

智能体可能检索一次后发现证据不够，再回去补充资料。到第三个阶段不等于完成了 60%，所以本次没有伪造完成率。

运行页新增三个能核对的摘要：

- 阶段图：使用后端公开状态，表示研究计划、检索、核验、整理和保存。等待审批、补充信息、排队或暂停时，不把旧阶段误画成正在执行；完成、失败、取消或证据不足后，仅显示最后上报阶段，不保留当前执行高亮。
- 证据分布：分别统计支持、冲突、背景、待核验和已排除记录。图形旁保留文字和数量，不要求用户仅靠颜色理解。
- 步骤预算：使用已上报步数与上限；没有数据就明确说明尚未上报，不虚构费用。

实现位置：`ResearchOverview.tsx`。图不是模型的隐藏思考过程，也不是结论准确率。

## 5. 资料库为什么换成列表

查资料时通常需要比较名称、版本和索引状态，紧凑列表比一堆大卡片更方便扫读。仍保留卡片切换，以适应不同查看习惯。

筛选条件写入 URL（浏览器地址）：刷新后能恢复搜索文字、空间、类型和视图。已有的演示标记及来源引用参数不会被覆盖。固定查看某个来源时，另提供“查看全部资料”，避免用户不知道如何退出。

实现位置：`LibraryCatalog.tsx` 和 `library-filters.ts`。URL 筛选状态只是界面偏好，不是修改资料或扩大一次研究的证据范围。

## 6. 手机与键盘怎么保证可用

手机菜单打开时，背景内容暂时不能操作，键盘在菜单内循环。Esc 可以关闭并回到打开按钮；把窗口拉宽时，菜单自动关闭并恢复正文操作。

实际检查发现折叠的开发入口仍可能被算入焦点列表，已显式排除这些隐藏项；遮罩也不进入键盘切换顺序。这是本轮浏览器检查发现并修复的具体问题。

`inert` 表示背景区域暂时不能接收交互；`aria` 是向读屏软件说明控件含义和状态的属性。它们是帮助用户操作的机制，不是视觉装饰。

## 7. 开源项目是怎么用的

已拉取 [shadcn/ui](https://github.com/shadcn-ui/ui) 与 [Tremor](https://github.com/tremorlabs/tremor) 官方源码，借鉴它们的导航、工具栏、列表、加载轮廓和分段数据展示。

shadcn/ui 是可定制的界面组件集合；Tremor 偏向数据看板组件。本轮没有直接复制组件、安装它们的依赖或执行它们的项目脚本，而是在现有技术栈中实现相应设计，避免仅为美化引入另一套框架。

具体提交与许可见 [spec.md](spec.md)；实际验证与未覆盖范围见 [acceptance_report.md](acceptance_report.md)。这轮按界面改造、React 性能、界面可访问性与双轴代码审查技能执行。

## 这轮不代表什么

不代表已接入真实大模型、不代表真实服务全链路已经验收、不代表已经部署到公网。本轮预览使用明确标记的固定演示数据，供查看页面与练习流程。
