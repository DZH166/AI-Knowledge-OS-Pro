## 本轮发现并修复的问题

1. 手机菜单展开后把窗口拉宽，正文仍可能被 `inert` 禁用：加入与样式一致的 981px 断点监听，关闭菜单。
2. 只有延后筛选仍不足以隔离每次输入的旧列表渲染：把资料选择和资料库整列表设为 memo 边界，稳定参数和回调，并复用统计结果。
3. 预算摘要重复写 4/8/16：复用原有 `BUDGETS`。
4. 等待审批时上报 phase 可能仍停在旧阶段：显示等待状态和最近上报阶段，不高亮为当前执行。
5. 折叠 details 的子链接仍有布局框，导致手机键盘焦点逃出菜单：排除折叠子项与负 tabIndex，遮罩不进入键盘顺序；修复后实测双向循环通过。
6. 正式预览复核发现结束任务仍会高亮旧 phase：补充完成/失败/取消/证据不足反例，先确认测试失败，再取消终止态的当前高亮，并将标签改为“最后上报阶段”。

检查命令说明：一次附加临时 `core.autocrlf=false` 的诊断把现有 Windows CRLF 行尾报告成尾随空白；该选项只作用于单次命令，没有修改仓库配置。随后按仓库原配置重跑 `git diff --check` 通过，没有为消除这类诊断输出而改写旧文件或历史日志。
