# 3 分钟 Demo 脚本（照着做即可）

目标：让面试官在 3 分钟内看到“引用可回放 + 任务可恢复 + 存储有证据”，而不是听你念技术名词。

## 录屏前准备

- 用 `DEMO_MODE=true` 和 showcase 演示库，不要用真实私人资料。
- 浏览器缩放 100%，窗口 1440×900；关闭通知和无关标签页。
- 先跑一次 `python scripts/seed_showcase.py --database-path backend/data/demo_showcase.db --reset`，保证数据干净。
- 准备好工作台、运行记录、证据资料库三个页面。
- 如果现场网络不稳，录屏 + 本地 demo 是主方案，在线 URL 只是加分。

## 0:00–0:20 开场

画面：工作台首页。

嘴里说：

> “普通 RAG 能回答，但很难证明这句话来自哪一版资料的哪个片段。我做的系统把引用变成可回放的证据链。”

不要一上来报技术栈。

## 0:20–1:10 主流程（Agent run → evidence ledger → citation jump）

### 名词翻译

- **Agent run**：你提交的一次研究任务。系统会计划、检索、判断证据够不够，再生成结果。
- **Evidence ledger**：这次任务用到的证据台账。每条证据记录来源、版本、片段和位置。
- **Citation jump**：点击回答里的引用，直接跳到原文页码、视频时间戳、图片区域或代码行。

### 操作

1. 在工作台选择一个知识空间。
2. 输入一个跨文档问题，例如：
   > “这套系统如何保证多模态回答可以追溯到原始证据？”
3. 点击提交，展示计划/检索/评估步骤。
4. 打开生成的 Artifact（研究产物）。
5. 点击引用，跳到 PDF 页码或视频时间戳。
6. 鼠标指一下 revision / chunk / hash / locator。

嘴里说：

> “这里不是只存 source_id，而是固定 revision、chunk、hash 和 locator。所以来源更新后，旧回答仍然能回放到当时那一版。”

## 1:10–1:50 可靠性（cancel/recover）

### 名词翻译

- **Cancel**：取消一个正在跑的任务。
- **Recover**：刷新/重连后继续看同一个任务，不重复执行。
- **Fence**：取消之后，迟到的模型结果不允许再写回状态。

### 操作

1. 启动一个较慢的 Agent run。
2. 点击取消。
3. 刷新页面，重新打开运行记录。
4. 指出状态仍然是取消/已恢复，没有重复任务。

嘴里说：

> “取消不是把前端按钮变灰。系统会推进 epoch，迟到的结果会被 fence 拒绝，避免旧结果污染新状态。”

## 1:50–2:20 质量（评测）

### 名词翻译

- **60/60**：60 个固定合成场景全部通过，不是 60 个真实用户。
- **Citation completeness**：每个事实 claim 是否都有引用。
- **Hit@1/5 / MRR**：检索指标，衡量正确片段排在第几位。

### 操作

1. 打开评测页。
2. 指出 60/60、citation 1.0。
3. 补一句“这是合成固定集”；再指中文检索 24 题。

嘴里说：

> “合成集用于回归，不冒充真实模型质量。真实 provider 我会另跑 20 题，单独记录延迟、成本和失败案例。”

## 2:20–2:50 存储（storage check）

### 名词翻译

- **Storage check**：只读自检，检查数据库、文件、版本台账是否一致。
- **SHA-256 manifest**：备份里每个文件的指纹清单。
- **Orphan**：数据库没引用、但磁盘上存在的文件。

### 操作

1. 打开“证据资料库”。
2. 展示“存储完整性”面板。
3. 勾选“核对内容指纹”，点击“重新检查”。
4. 指出：引用文件 8、缺失 0、孤儿 0。

嘴里说：

> “备份不是复制一个 SQLite 文件。归档带逐文件 SHA-256，恢复前完整验证；换目录恢复还会重写数据库里的绝对路径。”

## 2:50–3:00 收尾

> “当前是单用户本地工作台，SQLite；多租户和公网部署是下一步，不是现在假装有。”

这句话会加分：说明你知道边界。
