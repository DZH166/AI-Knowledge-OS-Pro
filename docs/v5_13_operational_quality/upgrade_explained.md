# V5.13 升级解释（给使用者与面试复盘）

## 这一轮到底改了什么

### 1. 先让项目“能启动、能测完”

全量审查时发现三类问题：文档写了逗号分隔的 CORS 配置，代码却只接受 JSON，换台机器启动就会崩；Windows 下 ffmpeg 输出按本地编码读取失败，视频时长被写成 1ms，还级联出大量测试错误；部分测试子进程的编码不一致，导致 `stdout=None`。

修复不是加一层 `try/except`，而是把边界写清楚：配置解析同时接受两种已文档化格式；所有外部进程显式 UTF-8；测试两侧统一编码。结果从 `11 failed / 89 errors` 收敛到 **1013 passed / 4 skipped / 0 failed**。

### 2. 界面：干净不是少放东西，而是每个区域只做一件事

- 主路径仍然是四个入口：研究工作台、运行记录、证据资料库、研究成果。
- 摄取、任务、学习、媒体详情等开发者页面统一中文；不再出现 “Choose Files” 这类浏览器原生英文。
- 五列工作流、四列卡片在 1180/1024 有明确断点，移动端不横向溢出。
- 证据资料库直接展示“存储完整性”：引用文件、缺失文件、活跃来源、数据库体积、Journal 模式。
- 工作台在提交前显示 AI 服务准备度；缺什么就写清楚，不再等提交后才发现。
- 新增 12 个页面无障碍巡检：单 h1、按钮有可访问名称、图片有 alt、无横向溢出。

### 3. 存储：从“文件在”升级为“内容对得上、能恢复”

- 上传写入后 `fsync`、核对实际大小；失败清理残留文件。
- SQLite 使用 WAL + `synchronous=FULL` + 外键约束。
- 只读自检检查数据库完整性、外键、活动版本/索引台账、文件存在性/大小/可选 SHA-256、孤儿文件。
- 备份用 SQLite 在线备份 API，归档带逐文件 manifest；创建后立即复核，失败删除半成品。
- 备份前把上传文件与数据库登记指纹交叉核对；演示种子曾把哈希写成固定标签，这一轮已改成实际字节哈希。
- 恢复前完整验证；目标非空时保留旧数据库和旧上传目录；上传根目录变化时自动重写数据库里的绝对路径，避免恢复后全部变成孤儿。

### 4. RAG：把“追问”变成可检索的上下文

聊天里的“它/这个/上述”短追问，会把上一轮问题并入检索 query；但回答、历史和引用仍然只对应原始问题。页面会提示“追问检索已结合上一轮问题”。这不是同义词理解，也不伪造模型能力。

### 5. AI：语言一致性与准备度

Agent 的计划、追问、综合被明确要求使用与目标相同的语言；RAG 仍然只基于检索上下文回答，缺资料时明确拒绝。固定 60 案例评测保持 60/60，多跳任务相对单次检索提升 33.33pp；中文 24 题严格模式双路径 Hit@1/5 = 1.0。
