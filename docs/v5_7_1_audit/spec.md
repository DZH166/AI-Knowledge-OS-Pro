# V5.7.1 发布后审计与修复

基线：已发布 V5.7，提交 f7577ea95f00ef6822ab957c8e8e63e4e951a2f7。
本阶段重新验证已有功能并修复实际缺陷；V5.8 反馈系统尚未实现。

## 必须满足

- 执行入口与恢复入口共同执行累计评测预算、截止时间和 Study 状态限制。
- 同一 Study 的创建轮次、任务认领、取消与结果落库按数据库写锁串行化。
- 每次执行有独立租约标识，旧尝试不能借同一 Worker 名覆盖新尝试。
- 评测结果、评分、推荐在同一事务内保存；GET 查询不产生写入。
- 并发转换同一 Trial 只产生一个策略草稿、一条转换事件；失败全部回滚。
- 暖启动观察在子 Study 创建时冻结；旧库只保存迁移时仍可读取的父数据，并明确标识。
- 推荐按评分与稳定序号排序；必须有真实基准 Trial，完整硬门与有效报告。
- 导出比较验证 Trial/报告/策略身份，并覆盖 3 个 Trial 的全部两两分类比较。
- HTTP 拒绝无时区截止时间；重放既有命令保持兼容，变更截止时间必须冲突。
- 页面自动更新后台进度，网络/结构错误可见，重试同一用户意图保留请求标识。
- 分享列表从服务器恢复，刷新后仍能撤销；只读分享禁止缓存，过期链接返回 404。
- 数据迁移向上/向下验证；全量前后端检查；浏览器串起自动完成、三方比较和刷新后撤销。

## 明确边界

固定评测验证录制模型下的程序行为，不代表真实大模型质量；独立生产构建与开发服务器浏览器测试分别报告。
旧 V5.6 已覆盖丢失的历史请求无法凭空恢复；从 V5.7 命令表建立后保存每个请求。
观察引导候选生成使用线性趋势与随机探索，没有贝叶斯后验或不确定性估计。
