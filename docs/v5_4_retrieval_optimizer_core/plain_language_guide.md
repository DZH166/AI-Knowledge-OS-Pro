# V5.4A 通俗指南（Plain Language Guide）

## 这个阶段做了什么？

想象你有一个"检索策略"调音台，上面有 7 个旋钮：

- 每种查询各取多少条证据（事实类 top_k、对比类 top_k、时序类 top_k）
- 证据的最低及格分（minimum_score_millis）
- 每个来源最多引用几条（max_hits_per_source）
- 上下文前后各带多少段（neighbor_before / neighbor_after）

V5.4A 建了一个**自动调音师**：它按你给的旋钮范围，自动拧出几十种组合，
每一种组合都用同一套 60 道固定考题测一遍，最后告诉你"哪几组成绩最好、
为什么值得看"。

## 几个核心概念的白话解释

**Optimization Study（优化实验）**
一次完整的"自动调音"任务。你告诉它：基准策略是什么、最多试几组、
考题最多跑几遍、什么时候必须停（deadline）、随机种子是几。

**Candidate（候选）**
一组具体的旋钮位置。第 1 组永远是"现在的位置"（基准锚点），
后面几组由随机数生成器按你给的种子拧出来。同样的种子永远得到同样的
候选序列——所以实验可以被复现。

**Trial（试验）**
"用某组旋钮位置跑一遍 60 道考题"这件事。它不是直接在网页请求里跑的，
而是先写进数据库的待办清单（Outbox），由后台工人（RQ Worker）认领执行。
这样即使机器崩了，待办还在，重启后接着跑。

**Pareto Frontier（帕累托前沿）**
如果候选 A 在所有指标上都不比 B 差，还至少有一项更好，就说 A 支配 B。
前沿就是"没被任何人支配"的那批候选。落在前沿外的候选，看都不用看。

**Recommendation（推荐）**
推荐器从前沿里挑出值得人工审查的候选，并用一段话解释：哪些指标变好了、
哪些没变、哪些可能变差、为什么仍然值得看、每个数字的出处（SHA-256 指纹）。
**推荐只是建议，绝不会自动上线**——上线仍然要走 V5.3 那套需要 60/60 满分
评测的人工激活流程。

## 为什么值得相信它？

1. **成绩单不可伪造**：评测报告要过十道硬门（hard gate），任何一道不过
   就整体作废；报告里若出现密钥样式的文字直接拒绝。
2. **外部调用必须为零**：整个评测是本地的确定性程序，报告里
   `external_provider_calls` 不为 0 就作废。
3. **写结果要验工牌**：后台工人写结果时必须出示自己的租约（lease）；
   一个任务同一时刻只有一个合法工人，崩溃后的残留租约过期会被回收。
4. **晚到不覆盖新**：旧工人慢吞吞交上来的结果，因为工牌已经不匹配，
   数据库直接拒绝，不会覆盖新结果。

## 明确不做什么

- 不看页面、不做视觉设计（那是 V5.4B 的事）。
- 不接真实大模型（评测是确定性回放，不是模型质量基准）。
- 不自动上线任何策略。
