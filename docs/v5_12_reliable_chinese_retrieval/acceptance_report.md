## 第一步：任务事件接口异常

最小复现使用真实 SqlEvidenceAgent、隔离 SQLite 和公开 HTTP 接口。同一不存在任务的详情正常返回 `404 / RUN_NOT_FOUND`，事件接口却在响应体生成期间传播 ServiceError，无法返回结构化 404。命令：`python -m pytest backend/tests/test_v5_12_agent_stream.py -q --tb=short --basetemp=.pytest_tmp/v512_stream_red_55cf723e46ac4768a7632c4da079b0ae`，`1 failed`（31.12 秒）。这是对旧云端异常时机的直接复现；本机暴露的是原始 ServiceError，不冒称每个环境都出现同一句 RuntimeError。

修复仅在构造 StreamingResponse（持续发送进度的响应）之前调用已有公开任务查询；缺失错误由现有错误处理器和请求编号中间件返回。没有预读首个事件，不让正常空闲连接等待心跳，也没有重建任务或追加事件。首条修复后 `1 passed`（11.42 秒）。

随后逐片补齐并通过 11 个公开 HTTP 回归：五种游标入口下的完整 404、真实创建/取消任务后的 SSE 头和事件、指定位置恢复、终点空流、Last-Event-ID 双向优先、初次/未来游标的状态同步和重放、负 after 的结构化 422。连同旧 API 和运行时测试共 `39 passed`（32.91 秒），独立目录 `.pytest_tmp/v512_stream_api_runtime_3e19e2560284467fbbdf52b982538e17/`。静态检查和差异空白检查通过。

独立只读审查确认该查询仅短会话读取，不提交数据、不追加事件、不等待心跳；规范违规 0、需求缺失/超范围/实现错误均为 0。保证范围是请求校验时任务已经不存在；前检后被外部硬删除、数据库故障或流中错误仍可能中断连接，不宣称所有后台异常已经消失。
