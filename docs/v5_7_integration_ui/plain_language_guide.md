# 溯知 V5.7 通俗解释：让 Agent 学会安全地优化自己的检索方法

## 先用一句话说明

V5.7 没有让大模型偷偷改系统，而是增加了一间“检索实验室”：系统复制当前检索策略，生成几个候选方案，用同一套 60 道固定题考试，比较质量、速度和检索规模，最后把建议交给人决定是否采用。

## 页面上的词是什么意思

- **Agent（智能体）**：不只回答一句话，而是会按步骤规划、检索、检查证据、生成结果并保存执行过程的程序。
- **RAG（检索增强生成）**：先从知识库找证据，再让模型根据证据回答。RAG 是这个 Agent 的证据引擎。
- **Study（优化实验）**：一次完整的策略优化任务，包含基准策略、目标、预算、若干候选和最终推荐。
- **Trial（候选实验）**：Study 里的一套具体检索参数，例如事实问题取多少段、最低相关分数是多少。
- **Policy（策略）**：Agent 检索证据时使用的一组规则和参数。
- **Snapshot（快照）**：把当时的策略完整保存下来；以后即使当前策略变了，历史实验仍能准确复现。
- **Fingerprint（指纹）**：由策略内容计算出的 SHA-256 哈希值，用来确认“评测的就是这一份配置”，防止串数据。
- **Deterministic Evaluation（确定性评测）**：相同输入每次都得到相同结果的固定考试。当前优化器不会调用付费大模型，外部模型调用数必须为 0。
- **Hard Gate（硬性门禁）**：必须全部满足的安全条件，例如 60 个案例全部通过、引用完整、没有未授权动作。
- **Pareto Frontier（帕累托前沿）**：保留“没有被其他候选在所有指标上全面超过”的方案，避免只看一个总分。
- **Bayesian Optimization（贝叶斯优化）**：根据前几轮结果推测下一批更值得尝试的参数，同时保留少量探索；这里的算法固定随机种子，所以可以复现。
- **Draft（草稿）**：推荐方案转换后的待审策略。草稿不会自动上线，仍需人工评测和激活。
- **Outbox（事务消息表）**：先把“需要后台执行的任务”与业务数据一起写进数据库，再可靠地投递给队列，避免数据库成功但消息丢失。
- **Lease（执行租约）**：后台 Worker 在限定时间内取得任务执行权；超时后可由恢复流程接管。
- **Fence（写入栅栏）**：只允许仍持有有效租约的 Worker 写结果，阻止超时旧任务覆盖新结果。
- **Idempotency（幂等）**：同一个请求重复发送，只返回原来的结果，不重复创建 Study、轮次或草稿。
- **Migration（数据库迁移）**：把旧数据库安全升级到新结构。V5.7 会把 V5.6 已执行的下一轮请求补写到新收据表，防止升级后重复建轮次。
- **Run Trace（运行轨迹）**：某次 Agent 运行留下的持久化步骤、事件和结果记录。

## 一次实验实际上怎样运行

1. 用户选择“质量优先、平衡、成本优先”模板。模板规定搜索范围和权重，页面只允许缩小预算，不能偷偷扩大成本。
2. 后端读取当前活动 Policy，保存不可变 Snapshot 和 Fingerprint，再生成基准 Trial 与候选 Trial。
3. Outbox 把 Trial 交给 Redis/RQ。Redis 是消息与任务队列服务，RQ 是 Python 后台任务执行器。
4. 每个 Trial 跑同一套 60 案例，记录通过率、证据召回率、引用完整度、延迟、检索窗口和外部模型调用数。
5. 系统先检查 Hard Gate，再计算归一化分数和 Pareto Frontier；不合格方案不会进入推荐。
6. 如果继续下一轮，Bayesian Optimization 读取已有结果生成新候选，同时检查累计预算、指纹去重和历史请求收据。
7. Workbench 展示真实数据库中的轮次、指标、分类胜负、配置差异、事件和可校验报告，不用 Mock（假数据）补页面。
8. 推荐方案只能转换为 Draft。真正激活仍走 V5.3 已有的 60/60 人工门禁。

## 为什么它适合 AI 应用开发简历

这个阶段体现的不只是“会调用模型接口”，而是能把 AI 实验做成可靠产品：有数据版本、有后台任务、有失败恢复、有预算、有安全门禁、有可解释推荐、有前端工作流，也有数据库迁移和真实浏览器验收。面试时可以重点解释“为什么推荐不能自动上线”以及“怎样阻止旧 Worker 污染新结果”。

## 诚实边界

当前优化实验使用本地固定评测器，证明的是架构正确性、可复现性和工程可靠性，不代表真实大模型的最终回答质量。真实模型 Provider（模型服务提供方）的配置与线上质量/费用评测仍是后续阶段。
