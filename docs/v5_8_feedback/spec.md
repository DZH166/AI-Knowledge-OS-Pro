# V5.8 Reviewed Feedback — 结论反馈与人工审阅样例

基线：8876e949c0d0da9dddf005fc2c9a66e7c552922a（V5.7.1）。
本阶段完成成果页反馈、审阅工作台和可追溯的评测样例导出。复用现有资料、Agent 和评测入口；不配置模型，不改固定 60 场景，不自动优化/启用策略。

## 必须满足

1. 反馈只能指向数据库内已终结任务的最终成果；可针对整份成果或其中一条结论。拒绝不存在、跨成果结论、非最终成果和仍在执行的任务。
2. 服务器捕获任务目标、来源范围、策略身份、模型运行模式、成果正文、目标结论及该结论原有证据身份/定位/摘录，保存不可变快照与 SHA-256。客户端不能提交或覆盖这些事实。快照有明确大小上限；无效历史数据返回明确错误。
3. 四种问题类型：missing_evidence（漏找资料）、incorrect_answer（理解错误）、unsupported_citation（引用不支持）、incomplete_answer（回答不完整）。反馈说明不能为空并有长度限制；用户反馈作为不可信文本，不直接成为事实或工具指令。
4. 创建使用请求标识幂等：相同请求重放返回同一反馈，改变内容返回 409；并发重复提交只创建一份。重放不重新捕获已经变化的来源。
5. 反馈状态仅 pending / accepted / rejected。审阅带请求标识和期望版本；使用数据库串行化保护，只有一次终态审阅。相同请求重放成功，冲突/过时审阅明确 409。
6. 接受必须填写人工参考答案、验收要求和审阅理由，并选择 tuning（调参）或 holdout（留出测试）用途；允许标注快照内参考证据 ID，禁止跨反馈/跨任务注入其他 ID。无参考证据时明确为人工预期，不声称已完成事实验证。驳回必须有理由且不能夹带样例字段。
7. 接受状态、审阅记录和唯一评测样例在同一事务保存。驳回不生成样例；一个反馈不能同时进入两种用途。审阅者标记 local_user 仅表示本地操作来源，不冒充鉴权身份。
8. 列表使用稳定游标分页，支持状态与运行模式筛选；读取与导出不产生写入。返回反馈状态、快照、审阅与样例关联，刷新后仍可追溯。
9. 导出用户明确选择的 1–100 份已接受样例，必须属于同一用途与运行模式，拒绝缺失、重复、未接受、混合用途/模式的选择。规范 JSON 与 SHA-256 可重复；原始资料可能包含私人内容，页面必须提醒导出范围，且不自动外发。
10. 导出格式明确标注 human_reviewed_feedback_v1，不冒充现有固定评测器输入或已通过的真实模型质量成绩；不执行人工文本，不把反馈写入知识库，不启用任何策略。
11. 成果页加入反馈入口，Recording（浏览器内演示）无真实数据库成果时不允许伪提交；保存到后端的 demo/recording/real 任务显示真实运行模式。
12. /evaluations/feedback 审阅工作台从现有评测入口进入，不新增主导航。可以按状态/模式查看、逐条查看快照、接受/驳回、查看样例用途并导出。请求失败可见；同一意图重试保留标识；禁止并发重复点击；过时响应不能覆盖新页面。
13. 390px 窄屏、键盘和语义化标签可用。新的反馈内容以纯文本显示，不能执行 HTML/脚本。
14. Alembic 0017 新增数据结构；验证从已有数据升级、降级边界和再次升级。保留历史记录，不改旧迁移。
15. 测试先行逐片推进：公开 HTTP 接口 + 真实 SQLite、浏览器客户接口契约、真实后台浏览器流程。独立 Standards / Spec 审查后运行全量后端、前端、两次 Strict E2E、静态检查与发布门禁。

## 非目标与安全边界

没有真实模型配置；没有自动复跑新样例的评分器；没有把人工参考答案当成客观真理。资料入库和通用研究流程复用现有功能，本期新增的是“报告问题—审阅—积累评测样例”这一段。
项目仍是可信本地单用户模式，不新增公网发布、多用户鉴权或公开反馈链接。留出标签提供用途隔离，不等于对拥有本地数据库权限的开发者隐藏答案。

## 成品场景

技术资料研究助手：打开已完成且有引用的研究成果，指出一条结论的问题，人工核对原文并填写正确预期，接受为调参或留出样例，再导出带历史证据的样例包。拒绝一条错误反馈时，原成果和知识库保持不变。
